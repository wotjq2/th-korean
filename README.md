# 태국 사이트 한국어

태국 사이트를 **한국어로 검색**하는 유저스크립트입니다. 사이트가 늘어나도 **스크립트는 하나**, 용어집도 GitHub 의 [`th-korean-glossary`](https://github.com/wotjq2/th-korean-glossary) **하나**입니다. 사이트나 PC가 늘어도 단어가 흩어지지 않게 하기 위해서입니다.

현재 지원: 라자다 태국(`lazada.co.th`), 쇼피 태국(`shopee.co.th`). 추가 방법은 [새 사이트 추가하기](#새-사이트-추가하기) 참고.

현재 버전: **1.12.1**

## 왜 필요한가

태국 쇼핑몰은 한국어를 지원하지 않습니다.

- **한국어로 검색하면 결과가 엉뚱하게 나옵니다.** 검색 색인이 태국어/영어라 `차량 핸드폰 거치대` 로 검색하면 Roblox 기프트카드 같은 무관한 상품이 나옵니다. 태국어로 바꿔야 정상 결과가 나옵니다.
- **영어로 전환해도 상품명은 태국어 그대로입니다.** 메뉴만 영어가 되고, 상품 제목은 판매자가 쓴 태국어라 번역되지 않습니다.

## 역할 분담 (중요)

페이지 전체 번역은 **크롬 자동번역**이 훨씬 빠릅니다. 브라우저 내부에서 처리하기 때문에 유저스크립트가 HTTP로 왕복하는 방식과는 비교가 안 됩니다. AI는 더 느립니다.

그래서 이렇게 나눕니다.

| 무엇 | 누가 | 이유 |
|---|---|---|
| 페이지 전체 표시 | **크롬 자동번역** | 가장 빠름 |
| 한국어 → 태국어 검색 | **이 스크립트 (용어집)** | 크롬이 못 하는 유일한 것. 용어집 조합이라 API 없이 즉시 |
| 헷갈리는 상품명 하나 | **선택 번역 (AI)** | 정확도가 필요하고 한 줄이라 느림이 체감 안 됨 |

권장 설정: `페이지 표시 번역 엔진` = **끄기**, 크롬 자동번역 **켜기**.

### 쇼피에서 크롬 번역이 자동으로 안 뜨는 이유

라자다는 주소창에 번역 아이콘이 뜨는데 쇼피는 안 뜨고, 우클릭으로 번역해도 `항상 번역` 메뉴가 없습니다. 두 사이트의 첫 HTML을 받아 비교한 결과입니다.

| | 쇼피 | 라자다 |
|---|---|---|
| `<html>` | `<html dir="ltr">` — lang 없음 | lang 없음 |
| 태그 걷어낸 본문 | **0자** | **8,000자** (태국 문자 374자) |
| `notranslate` | 없음 | 없음 |

크롬은 페이지를 다 읽은 시점에 `<html lang>` 과 본문 글자로 언어를 한 번 정합니다. 쇼피는 화면을 전부 JS로 그려서 그 시점에 **볼 글자가 하나도 없습니다.** 그래서 언어가 `감지된 언어`(미확정)로 남습니다.

- 번역 아이콘은 언어를 특정했을 때만 나옵니다 → 안 뜸
- `항상 번역` 은 "이 **언어**는 항상" 이라는 언어별 규칙이라, 언어 이름이 없으면 만들 수 없습니다 → 메뉴에서 사라짐

쇼피도 나중에 JS로 `lang="th"` 를 붙이지만 크롬의 판단이 끝난 뒤라 소용없습니다. 그래서 **1.5.1 부터 스크립트가 `document-start` 에서 `<html lang="th">` 를 먼저 박아 둡니다** (`SITES.shopee.langHint`). 사이트가 이미 `lang` 을 선언해 뒀으면 건드리지 않습니다.

그래도 안 뜨면 번역 버블의 ⋮ → `페이지가 감지된 언어로 표시되지 않음` → **태국어** 를 고르세요. 크롬에게 원본 언어를 직접 알려주는 항목이고, 그 뒤 ⋮ 를 다시 열면 `태국어 항상 번역` 이 생깁니다.

현재 `lang` 값은 **Tampermonkey 아이콘 → `검색창 인식 상태 확인`** 에서 볼 수 있습니다.

## 설치

어느 PC에서든 크롬 + Tampermonkey 만 있으면 됩니다. 크롬 주소창에 입력:

```
https://raw.githubusercontent.com/wotjq2/th-korean/main/th-korean.user.js
```

Tampermonkey 설치 화면이 뜨면 **설치**(이미 깔려 있으면 **업데이트**). 이름이 `태국 사이트 한국어` 로 보여야 정상입니다. 복사-붙여넣기는 쓰지 마세요 (아래 "겪었던 문제" 참고).

**API 키는 필요 없습니다.** 검색은 용어집 + 무료 API, 선택 번역도 키가 없으면 무료 API로 동작합니다.

**업데이트** — 스크립트의 `@updateURL` 이 위 GitHub 주소라, 이 저장소에 새 버전을 올리면 각 PC의 Tampermonkey 가 알아서 받아 갑니다(하루 한 번 확인). 바로 받으려면 Tampermonkey 대시보드의 `업데이트 확인`. GitHub 원본 주소는 몇 분 캐시가 있어 올린 직후에는 옛 버전이 보일 수 있습니다.

**용어집은 GitHub 한 곳** — 검색 용어집은 [`th-korean-glossary`](https://github.com/wotjq2/th-korean-glossary) 저장소의 `glossary.txt` 하나이고 모든 PC가 같은 것을 받아 씁니다. 단어는 설정 패널에서 바로 저장합니다(아래 [용어집에 단어 넣기](#용어집에-단어-넣기)).

**PC마다 따로인 것** — 설정 패널(**한** 버튼)의 선택 값(검색 전 확인, 페이지 번역 엔진 등), GitHub 연결 토큰, AI 키만 그 브라우저에 저장됩니다.

**크롬 확장 설정에서 `사용자 스크립트 허용` 을 켜야 합니다.** 최근 크롬은 개발자 모드가 아니라 확장별 이 토글로 바뀌었습니다.

### 고치면서 시험할 때 (로컬 서버)

GitHub 에 올리기 전에 이 PC에서 먼저 돌려 볼 때만 씁니다.

```bash
node "E:/Production program/web translator/serve.js"
```

`http://localhost:8765/th-korean.user.js` 로 설치하면 파일을 고칠 때마다 같은 주소로 다시 설치해 확인할 수 있습니다. 서버는 요청마다 파일을 새로 읽습니다. 다만 이렇게 설치해도 `@updateURL` 은 GitHub 이므로, 다음 자동 업데이트 때 GitHub 버전으로 돌아갑니다. 확인이 끝나면 GitHub 에 올리세요.

### 1.5.0 은 "업데이트"가 아니라 "설치"로 뜹니다 (한 번만)

Tampermonkey는 `@name` + `@namespace` 로 같은 스크립트인지 판단합니다. 이 둘이 바뀌면 업데이트가 아니라 **새 스크립트**로 취급됩니다.

1.5.0 에서 이름을 사이트가 안 들어간 `태국 사이트 한국어` 로 **고정**했습니다. 앞으로 사이트를 몇 개를 추가하든 이 줄은 건드리지 않으므로, 이번 한 번만 설치로 뜨고 이후로는 계속 업데이트로 받습니다.

설치 후 할 일:

1. Tampermonkey 대시보드에서 **옛 스크립트(`라자다 …` 로 시작하는 것)를 삭제**하세요. 안 지우면 라자다에서 두 개가 동시에 돌아 **한** 버튼과 번역이 두 번씩 작동합니다.
2. **API 키와 직접 추가한 용어집을 다시 넣으세요.** 설정은 스크립트별로 저장되므로 새 스크립트로 넘어오지 않습니다. 기본 용어집은 스크립트에 들어 있어 그대로입니다.

## 사용법

### 검색

검색창에 한국어로 입력하고 **Enter**. 태국어로 바뀌면서 바로 검색됩니다.

검색어는 **용어집 단어로 쪼개서 태국어를 이어 붙입니다.** 통째로 용어집에 없어도 단어마다 있으면 API를 한 번도 부르지 않고 즉시 끝납니다.

```
차량 핸드폰 거치대        → 차량 + 핸드폰 거치대       → ที่วางโทรศัพท์มือถือ รถยนต์
여성용 방수 운동화        → 여성용 + 방수 + 운동화      → รองเท้าผ้าใบ กันน้ำ ผู้หญิง
아이폰 15 프로 케이스 투명 → 아이폰 15 프로 + 케이스 + 투명 → เคส iPhone 15 Pro ใส
돼지막창 냉동 / 냉동 돼지막창 → 돼지막창 + 냉동          → ไส้ใหญ่หมู แช่แข็ง
강아지용 샴푸             → 강아지(용) + 샴푸          → แชมพู สุนัข
27인치 모니터             → 27인치 + 모니터            → จอมอนิเตอร์ 27 นิ้ว
무선 이어폰 추천          → 무선 이어폰 (+ 추천은 뺌)   → หูฟังไร้สาย
```

- 띄어 쓰지 않아도 쪼갭니다(`무선이어폰`, `여성운동화`, `갤럭시S24울트라케이스`).
- 태국 상품명 순서로 잇습니다: **상품 이름이 먼저, 꾸밈말(색·소재·성별·크기·냉동·브랜드·크기 숫자)이 뒤**. 한국어로 꾸밈말을 앞에 치든 뒤에 치든 같은 결과가 나옵니다. 상품 이름끼리는 뒤집습니다(`고양이 모래` → `ทราย แมว`). 영문·숫자(`iPhone 15 Pro`)와 숫자에 붙은 단위(`27 นิ้ว`)는 한 덩어리로 순서를 지킵니다.
- 어느 말이 꾸밈말인지는 용어집 칸 제목의 `@꾸밈말` 표시로 정합니다(`# --- 색 @꾸밈말 ---`). 설정 패널에서 추가한 말은 상품 이름으로 봅니다.
- `추천` `인기` `후기` `가성비` 같은 말은 검색에 잡음만 되므로 뺍니다.

**용어집에 없는 말만** 무료 API(구글 번역)로 채웁니다. 조각이 짧아 요청 한 번이면 됩니다. 이때 토스트에 `용어집에 없던 말: 사무실 → …` 이 뜨니, 자주 쓰는 말이면 용어집에 넣어 두세요(아래). 모든 PC에서 다음부터 API 없이 검색됩니다.

### 용어집에 단어 넣기

1. **한** 버튼 → 맨 위 **검색 용어집** 칸에 `사무실=สำนักงาน` 처럼 적습니다(여러 줄 가능).
2. **저장**. GitHub 용어집에 바로 저장되고 칸은 비워집니다.

- 이 PC는 바로, 다른 PC는 10분 안에 반영됩니다.
- 이미 있는 단어를 적으면 그 뜻으로 고칩니다(그 줄 제자리). 새 단어는 파일 맨 끝 `설정 패널에서 추가한 단어` 칸에 쌓입니다.
- 두 PC에서 거의 동시에 저장해도 서로 지우지 않습니다(한쪽이 다시 받아 합칩니다).

**처음 한 번 — GitHub 연결 (PC마다)**

스크립트가 GitHub 에 대신 저장하려면 토큰이 필요합니다. 크롬의 GitHub 로그인은 github.com 웹페이지에서만 통하고 스크립트가 빌려 쓸 수 없기 때문입니다. 연결 전에 저장을 누르면 패널이 안내를 펼쳐 줍니다.

1. **한** 버튼 → **GitHub 연결** → **토큰 만들기** (GitHub 새 토큰 화면이 열림)
2. Expiration: 길게(고를 수 있으면 No expiration)
3. Repository access: **Only select repositories → `th-korean-glossary`** — **이것 하나만**
4. Permissions: **Contents → Read and write**
5. **Generate token** → 나온 `github_pat_…` 를 패널에 붙여 넣고 **연결 확인**

한 번 만든 토큰은 다른 PC에도 똑같이 넣어 쓰면 됩니다. 토큰은 그 PC의 Tampermonkey 에만 저장되고 GitHub API 에만 보냅니다. **다른 저장소나 권한은 주지 마세요** — 이유는 [보안](#보안-저장소-구성) 참고.

**예전에 이 PC에만 넣어 둔 단어** — 1.10.0 전에는 설정 패널에 넣은 단어가 그 PC에만 저장됐습니다. GitHub 에 없는 그런 단어가 남아 있으면 패널을 열 때 칸에 미리 넣어 둡니다. 그대로 **저장**하면 GitHub 로 옮겨지고, 칸을 지우고 저장하면 버립니다.

스크립트는 받은 용어집을 브라우저에 사본으로 두고 10분마다 GitHub 에서 새로 받습니다. GitHub 에 잠시 닿지 않아도 사본으로 계속 동작합니다. 바로 받으려면 Tampermonkey 메뉴 → `용어집 새로 받기`.

토스트에 번역 출처가 표시됩니다: `(용어집)` `(용어집 조합)` `(용어집 + 무료 API)` `(캐시)` `(무료 API)` `(NVIDIA NIM)` `(Groq)`.

검색어가 어떻게 쪼개지는지는 **Tampermonkey 아이콘 → `용어집에서 단어 찾아보기`** 에 검색어를 통째로 넣으면 보입니다. 어느 말이 비었는지 바로 나옵니다.

`검색 전 번역된 태국어 확인` 을 켜면 Enter를 한 번 더 눌러야 검색됩니다 (기본 꺼짐).

### 선택 번역

태국어 상품명을 **드래그**하면 아래에 `한국어로` 버튼이 뜹니다. 누르면 원문과 번역을 함께 보여줍니다. AI 키가 있으면 AI가, 없으면 무료 API가 처리합니다.

### 설정 (우측 하단 **한** 버튼)

| 항목 | 설명 |
|---|---|
| 페이지 표시 번역 엔진 | `무료 API` / `AI` / `끄기` — 크롬 번역을 쓴다면 **끄기** 권장 |
| 용어집에 없는 검색어는 | `그 말만 무료 API로 채우기` (기본, 빠름) / `통째로 AI에 맡기기` (정확, 검색마다 몇 초). 어느 쪽이든 용어집을 먼저 봅니다 |
| 검색 전 확인 | Enter 두 번 여부 |
| 선택 번역 | 드래그 시 버튼 표시 여부 |
| 검색 용어집 (맨 위) | `한국어=태국어` 를 적고 **저장** → GitHub 용어집에 바로 저장, 칸은 비워짐 |
| GitHub 연결 (접이식) | 용어집 저장용 토큰. PC마다 처음 한 번 |
| 표시 고정 | `원문=한국어`. 브랜드명이 번역되는 것을 막음 |
| AI 설정 (접이식) | 공급자·키·모델 |

### AI 연결 (선택)

없어도 전부 동작합니다. 정확도만 올라갑니다.

- **NVIDIA NIM** — [build.nvidia.com](https://build.nvidia.com) 에서 `Generate API Key` (무료). 약관에 입출력이 기록된다고 명시돼 있음
- **Groq** — [console.groq.com](https://console.groq.com)

키를 넣고 **`불러오기`** 를 누르면 모델 목록을 받은 뒤 **실제로 시험 번역을 한 번 해서** 키가 유효한지 확인합니다. NVIDIA는 모델 목록을 키 없이도 내주기 때문에 목록만으로는 검증이 안 됩니다.

## 동작 방식

**검색 가로채기** — `window` 캡처 단계에서 Enter/submit/클릭을 가로챕니다. 요소에 직접 붙이면 사이트가 먼저 등록한 핸들러가 이기기 때문입니다. `@run-at document-start` 로 페이지가 그려지기 전에 장착합니다.

**제출** — 폼에 맡기지 않고 주소를 직접 만들어 이동합니다. 사이트가 검색어를 자기 JS 상태로 들고 있어서, 입력창 값만 바꾸면 제출 때 한국어가 되살아납니다.

```
라자다: https://www.lazada.co.th/catalog/?q=<태국어>
쇼피  : https://shopee.co.th/search?keyword=<태국어>
```

**안전망** — 그래도 한국어가 주소에 들어가면, 결과 페이지에서 감지해 태국어로 바꿔 다시 검색합니다. 자동완성 클릭·북마크 등 어떤 경로로 들어와도 걸립니다.

**용어집** — [`th-korean-glossary`](https://github.com/wotjq2/th-korean-glossary) 의 1,477개 쇼핑 용어가 API를 거치지 않고 직접 매핑됩니다. 무료 번역기(구글)는 빠르지만 한국어를 영어로 한 번 거쳐서 다른 뜻으로 옮기는 일이 잦습니다. 용어집은 그런 말을 먼저 가로챕니다.

`가방` 은 실제로 확인한 오역이고, 나머지는 영어를 거칠 때 빠지기 쉬운 뜻을 짚어 미리 막아 둔 것입니다.

| 한국어 | 빠지기 쉬운 뜻 | 용어집 |
|---|---|---|
| 가방 | 비닐봉지 (확인함) | กระเป๋า |
| 맨투맨 | 일대일 | เสื้อสเวตเตอร์ |
| 원피스 | 만화 제목 | เดรส |
| 김 | 사람 이름 | สาหร่าย |
| 돼지코 | 돼지의 코 | หัวแปลงปลั๊ก |
| 스킨 | 피부 | โทนเนอร์ |
| 킥보드 | 발로 차는 판 | สกู๊ตเตอร์ |
| 마녀공장 | 마녀의 공장 | Manyo |

검색 순서: **용어집(통째로) → 용어집 조합 → 용어집에 없는 말만 무료 API**(또는 설정에 따라 통째로 AI). 용어집에 걸리는 말이 하나도 없을 때만 검색어 통째 캐시를 보고, 없으면 검색어 전체가 무료 API로 갑니다. 용어집에 걸린 말이 있는데 통째 캐시를 먼저 보면 옛 오역이 되살아나기 때문입니다(아래 "캐시가 옛 오역을 되살림").

1.9.0~1.9.1 에서 늘린 것(497 → 1,477개):

- **다른 뜻으로 옮겨지는 말** — 콩글리시(맨투맨, 콘센트, 돼지코, 호치키스, 쿨토시), 동음이의어(김, 사과, 스킨), 브랜드(마녀공장, 조선미녀, 너구리, 설화수 등 한글로 치는 브랜드를 영문으로)
- **조합에 필요한 말** — 성별(남자·여성·아동), 색(빨간·검정·투명), 소재(가죽·실리콘·원목), 크기·성질(미니·대형·접이식·논슬립), 용도(캠핑·주방·차량용), 단위(인치·개입·2인용·3단)
- **조합용 머리말** — `걸이` `꽂이` `커버` `용품` `색` `향` `맛` 처럼 앞말과 붙어 뜻이 정해지는 말. `가방걸이 → ที่แขวน กระเป๋า`, `딸기맛 → รส สตรอเบอร์รี่`
- **분야별 빠진 상품** — 의류·신발·뷰티(한국 화장품 용어)·주방·식품·생활·유아·반려동물·스포츠·공구·문구·의약

한 글자 말(`차` `옷` `색` `병`)은 합성어의 **맨 끝**에서만 쪼갭니다. 앞에서도 쓰면 `차량 → 차(ชา) + 량` 처럼 엉뚱하게 쪼개집니다. 다 덮이지 않는 합성어는 아예 쪼개지 않고 무료 API로 넘깁니다.

혼자일 때와 조합될 때 뜻이 갈리는 말은 따로 처리합니다(`CONTEXT_FORMS`).

- `차` — 혼자면 마시는 차(ชา), 앞에 붙으면 자동차(`차 방향제 → น้ำหอมปรับอากาศ ในรถ`)
- `거치대` — 혼자면 휴대폰 거치대, 앞말이 있으면 받침대만(`모니터 거치대 → ขาตั้ง จอมอนิเตอร์`)

## 보안 (저장소 구성)

모든 PC의 스크립트가 GitHub 에서 자동 업데이트되므로, 누가 공개 저장소의 코드를 몰래 바꾸면 그 코드가 모든 PC에서 돕니다. 이를 막으려고 저장소를 셋으로 나눴습니다.

| 저장소 | 공개 | 내용 | 쓸 수 있는 것 |
|---|---|---|---|
| [`th-korean`](https://github.com/wotjq2/th-korean) | 공개 | 스크립트 코드. 모든 PC가 여기서 업데이트 | 계정 주인(이 PC에서 배포할 때)만 |
| [`th-korean-glossary`](https://github.com/wotjq2/th-korean-glossary) | 공개 | 용어집 `glossary.txt` (글자 데이터뿐) | 위 + 브라우저의 용어집 저장용 토큰 |
| `th-korean-private` | **비공개** | `main` = `th-korean` 과 똑같은 사본, `watch` = 감시 작업 | 계정 주인만 |

- **토큰과 코드를 떼어 놓음** — 브라우저에 두는 토큰은 `th-korean-glossary` 에만 쓸 수 있습니다. 토큰이 새어 나가도 바뀌는 것은 단어뿐이고, 코드는 건드릴 수 없습니다. 용어집 값은 검색어·화면 글자로만 쓰여(`encodeURIComponent`, `textContent`) 이상한 값이 들어와도 코드로 실행되지 않습니다. 잘못 바뀐 단어는 GitHub 기록에서 되돌리면 됩니다.
- **공개 저장소 변조 감시** — `th-korean-private` 가 6시간마다 공개 `th-korean` 을 받아 비공개 사본(`main`)과 파일 하나하나 비교합니다. 다르면 작업이 **실패**로 끝나 GitHub 가 메일을 보내고, 비공개 저장소에 `⚠ 공개 저장소 th-korean 이 사본과 다릅니다` 이슈가 열립니다(달라진 줄 포함). 새 파일이 몰래 더해진 것도 잡힙니다. 지금 바로 확인하려면 비공개 저장소 → Actions → `공개 저장소 변조 감시` → **Run workflow**.
- **배포할 때** — 새 버전은 비공개 사본과 공개 저장소에 **같이** 올립니다. 공개 저장소에만 올리면 감시가 변조로 판단합니다.

  ```bash
  git push private main
  git push origin main
  ```
- **알림이 오면** — 직접 올린 것이 아니면, 비공개 사본으로 공개 저장소를 덮어 되돌리고(`git push --force origin main`, 로컬이 사본과 같을 때) GitHub 비밀번호와 토큰을 바꾸세요. 각 PC는 Tampermonkey `업데이트 확인` 으로 되돌린 버전을 받습니다.
- **계정 자체** — 결국 모든 것은 GitHub 계정에 달려 있습니다. GitHub 2단계 인증(2FA)을 켜 두세요.

## 새 사이트 추가하기

코드는 스크립트 맨 위 `SITES` 표만 보고 움직입니다. 사이트를 추가할 때 손대는 곳은 **세 군데**입니다.

**1. `@match` 한 줄** (헤더)

```js
// @match        https://www.example.co.th/*
```

**2. `SITES` 에 항목 하나**

```js
example: {
  label: '사이트 이름',             // 화면 표시 + AI 프롬프트에 들어감
  host: 'example.co.th',
  match: /(^|\.)example\.co\.th$/,  // location.hostname 판정
  inputSelectors: [                 // 검색창. 앞에서부터 찾아 먼저 맞는 것을 쓴다
    'input[name="q"]',              // 클래스명은 빌드마다 바뀌므로 name/type/id 를 앞에
    'input[type="search"]',
  ],
  widgetSelector: 'form[role="search"]',   // 자동완성 목록 등 검색창 밖 Enter 를 잡는 범위
  buttonSelector: 'button[type="submit"]', // 검색 버튼 (type="button" 인 곳이 많아 클릭을 직접 가로챔)
  queryParam: 'q',                  // 주소의 검색어 파라미터 (안전망이 읽음)
  searchUrl: (q) => `https://www.example.co.th/search?q=${encodeURIComponent(q)}`,
  spa: false,                       // 주소만 바뀌는 사이트면 true
},
```

**3. `@description` 의 지원 목록** (표시용, 자유롭게)

**`@name` 과 `@namespace` 는 절대 건드리지 마세요.** 바꾸는 순간 업데이트 고리가 끊기고 설정이 초기화됩니다.

선택자를 모를 때는 임시로 `broadInputFallback: true` 를 넣어 두면 한국어가 든 텍스트 칸의 Enter 를 전부 검색으로 봅니다. **실제 DOM 을 확인한 뒤에는 꼭 끄세요.** 켜 두면 배송지·리뷰 같은 다른 입력칸에서도 Enter가 검색으로 튑니다.

확인은 해당 사이트에서 **Tampermonkey 아이콘 → `검색창 인식 상태 확인`**. 검색창·위젯·버튼 중 무엇이 맞았는지 알려줍니다. `SITES` 에 없는 사이트에서는 검색 기능이 꺼지고 콘솔에 경고가 뜹니다 (엉뚱한 사이트로 검색이 날아가지 않도록).

## 용어집 늘리는 법

한국어 쪽 단어는 **쿠팡 카테고리 트리**에서 가져옵니다. 대분류 → 중분류 → 소분류로 내려가면 소분류 이름이 곧 사람이 검색창에 치는 말입니다 (`빨래건조대`, `분리수거함`, `수세미/세척솔`).

브라우저 콘솔에서 이렇게 긁었습니다.

```js
// 페이지의 카테고리 사이드바에서 '현재 노드의 자식'만 뽑는다
async function kids(url){
  const doc = new DOMParser().parseFromString(await (await fetch(url)).text(), 'text/html');
  const rows = [...doc.querySelectorAll('li.filter-function-bar-category > label > a')].map(a => {
    let d = 0, p = a.parentElement;
    while (p) { if (p.matches?.('li.filter-function-bar-category')) d++; p = p.parentElement; }
    return { t: a.textContent.trim(), h: a.getAttribute('href') || '', d };
  }).filter(x => x.t);
  const max = Math.max(...rows.map(x => x.d));
  return rows.filter(x => x.d === max);   // 가장 깊은 층 = 자식
}
```

시작점은 로켓배송 페이지(`coupang.com` → 왼쪽 위 ☰)의 대분류 링크입니다. 한 번에 6개씩 끊어 돌리세요 — 더 많이 하면 브라우저 도구가 먼저 끊깁니다.

**뽑은 뒤가 진짜 일입니다.** 카테고리 이름 중 검색어가 아닌 것(`학년별 준비물`, `쿠팡 Only`, `1인가구 주방용품`)을 걸러내고, 태국어를 붙일 때 위 "겪었던 문제"의 두 함정 — 합성어 직역, 너무 넓은 단어 — 을 피해야 합니다.

**1.9.0 부터는 긴 검색어를 다 넣을 필요가 없습니다.** 검색어를 쪼개 조합하므로, `glossary.txt` 에 빠진 **단어 하나**만 넣으면 그 단어가 들어간 모든 검색어가 살아납니다. 검색 후 토스트의 `용어집에 없던 말` 을 그대로 옮겨 넣는 것이 가장 빠른 방법입니다. 다만 조합하면 뜻이 틀어지는 말(`노트북 거치대` 를 조합하면 노트북용 **휴대폰** 받침이 됨)은 통째로 넣어 두세요 — 통째로 있는 말이 조합보다 먼저입니다.

"너무 넓은 단어" 규칙의 예외: `매트` `커버` `받침대` `필터` 처럼 **다른 말과 붙어서만 쓰이는** 머리말은 넓어도 괜찮습니다. 혼자 검색할 일이 드물고, 조합되면 앞말이 뜻을 좁혀 줍니다.

## 겪었던 문제 (재발 방지)

- **NUL 바이트** — 캐시 키 구분자로 `'\u0000'` 을 썼더니 파일에 실제 NUL이 들어가, 윈도우 클립보드가 3550자에서 잘렸습니다. 붙여넣기가 계속 실패한 원인. 구분자를 `|` 로 교체.
- **리스너 위치** — 검색창 요소에 리스너를 붙이면 라자다 핸들러가 먼저 실행돼 한국어가 그대로 나갑니다. `window` 캡처로 올려야 함.
- **사이트 내부 상태** — `input.value` 에 태국어를 써도 라자다는 자기 상태(한국어)로 주소를 만듭니다. 네이티브 setter + `_valueTracker` 무효화로 상태까지 갱신하고, 제출은 직접 이동.
- **재시도 누락** — 번역 성공 여부 확인 전에 노드를 `seen` 처리해서, 무료 API가 한 번 거절하면 그 문구가 영영 태국어로 남았습니다.
- **UI 중복 번역** — 크롬 자동번역이 스크립트 UI(이미 한국어)를 다시 번역해 `"설정"` → `"아주 오래전 일이에요."` 가 됐습니다. `translate="no"` + `notranslate` + `skiptranslate` 로 제외.
- **바트 기호** — `฿`(U+0E3F)가 태국 문자 영역이라 가격에도 선택 번역 버튼이 떴습니다.
- **이름 = 신원** — 쇼피를 넣으면서 `@name` 을 `라자다 태국 한국어` → `태국 쇼핑 한국어 (…)` 로 고쳤더니, Tampermonkey가 다른 스크립트로 보고 업데이트가 아니라 설치로 떴습니다. 설치돼 돌아가던 건 계속 1.0.x 였습니다. 이름에서 사이트를 빼고 `태국 사이트 한국어` 로 고정한 이유입니다.
- **옛 스크립트가 남아서 새 것을 이김** — `도시락`이 계속 `อาหารกลางวัน`(점심 끼니)으로 나왔습니다. 파일·서버·용어집을 다 확인해도 정상이었는데, 옛 1.0.x 스크립트가 지워지지 않고 같이 돌면서 **먼저 등록된 쪽이 `window` 캡처 Enter를 가로채고** 있었습니다. 옛 용어집엔 도시락이 없으니 AI로 넘어간 것. **어느 쪽이 도는지는 설정 패널 제목으로 구분합니다** — `라자다 한국어 설정`은 옛것, `태국 사이트 한국어 설정 · <사이트>`가 현재 것입니다. 진단(`검색창 인식 상태 확인`) 첫 줄의 버전·용어집 개수로도 확인됩니다.
- **눈에 똑같은데 다른 글자** — 위 문제를 쫓다 확인한 것. 한글은 완성형(NFC)과 조합형(NFD)으로 저장될 수 있어 `도시락`과 `도시락`이 화면상 같아도 `!==` 입니다. 웹에서 복사해 붙인 단어가 NFD로 들어오면 용어집 조회가 영원히 빗나갑니다. 1.8.0부터 조회·저장 양쪽에서 NFC로 정규화하고 폭 없는 공백(U+200B 등)도 걷어냅니다. 의심되면 **Tampermonkey 아이콘 → `용어집에서 단어 찾아보기`** 로 코드포인트까지 볼 수 있습니다.
- **용어집 구멍 = 오역** — 용어집에 없는 말은 AI로 넘어가고, 거기서 한국어 합성어가 글자대로 쪼개집니다. 실제로 `빗자루 → ด้ามไม้กวาด`(빗자루의 **자루**=손잡이), `도시락 → อาหารกลางวัน`(점심 **끼니**)가 나왔습니다. 둘 다 용어집에 짧은 형태가 없어서였습니다(`도시락통`은 있었는데 `도시락`이 없었음). **사람이 실제로 치는 짧은 말**을 넣어야 합니다. 같은 실수를 막는 규칙 세 줄을 AI 프롬프트에도 박아 뒀습니다.
- **너무 넓은 태국어** — `거치대 = ที่วาง` 는 "놓는 자리"라는 뜻뿐이라 그것만으로는 상품이 안 걸립니다. `거울 = กระจก` 도 유리 전반(액정보호필름·유리컵)을 같이 가리킵니다. 각각 `ที่วางโทรศัพท์`, `กระจกเงา` 로 좁혔습니다. 용어집에 넣을 때 **그 단어만으로 상품이 특정되는지** 봐야 합니다.
- **AI 검색이 느림** — 검색어 번역 기본값이 AI였는데, 용어집은 검색어가 **통째로** 있을 때만 걸려서 `차량 핸드폰 거치대` 처럼 조금만 길어져도 전부 AI로 넘어갔습니다. 검색 한 번에 몇 초씩 기다려야 했습니다. 1.9.0 에서 검색어를 용어집 단어로 쪼개 조합하도록 바꾸고, 빈 곳만 무료 API로 채우게 했습니다. 기본값도 무료 API로 바꿨고, 예전에 AI로 저장된 설정은 한 번만 옮겨 줍니다(설정에서 다시 AI를 고르면 그대로 둠). 속도를 내 준 것은 무료 API가 아니라 **용어집 크기**입니다. 조합이 다 되면 요청이 0번입니다.
- **용어집이 PC마다 따로** — 기본 용어집은 스크립트 안에, 사용자가 넣은 단어는 그 PC 브라우저에 저장돼서, 한 PC에서 넣은 단어가 다른 PC에는 없었습니다. 1.10.0 에서 용어집을 스크립트 밖 GitHub `glossary.txt` 하나로 옮기고, 모든 PC가 그것을 받아 쓰게 했습니다. 단어를 고쳐도 스크립트 버전을 올릴 필요가 없습니다.
- **뒤에 친 꾸밈말이 앞으로 감** — 처음 조합은 한국어 순서를 통째로 뒤집었습니다(한국어는 꾸밈말이 앞, 태국어는 뒤라서). 그런데 `돼지막창 냉동` 처럼 꾸밈말을 뒤에 치면 뒤집은 결과 `แช่แข็ง ไส้ใหญ่หมู` 가 됐습니다. 태국 상품명은 `ไส้ใหญ่หมูแช่แข็ง` 순서입니다. 1.12.0 에서 용어집 칸에 `@꾸밈말` 표시를 달고, 상품 이름 → 앞에 친 꾸밈말 → 뒤에 친 꾸밈말 순서로 잇게 바꿨습니다. `아이폰 케이스` 도 `เคส iPhone`, `운동화 270` 도 `รองเท้าผ้าใบ 270` 으로 더 자연스러워졌습니다.
- **업데이트했는데 그대로** — 1.12.0 으로 올린 직후에도 `แช่แข็ง ไส้ใหญ่หมู` 가 나왔습니다. 브라우저의 용어집 사본이 `@꾸밈말` 표시를 달기 전에 받은 것이었고, 10분이 안 돼서 다시 받지 않았습니다. 표시가 없으면 새 규칙은 꾸밈말을 못 가려 예전처럼 뒤집습니다. 1.12.1 부터 사본에 받은 스크립트 버전을 적어 두고, **스크립트 버전이 바뀌면 사본이 몇 분 전 것이어도 새로 받습니다.** 바로 받으려면 Tampermonkey 메뉴 → `용어집 새로 받기`.
- **최근 검색어가 옛 오역을 되살림** — 용어집에 `돼지막창=ไส้ใหญ่หมู` 를 넣은 뒤에도 `돼지막창` 을 누르면 `หมูหมากช้าง`(구글이 만든 엉터리 말)으로 검색됐습니다. 누른 것은 검색창 아래 **최근 검색어**였습니다. 예전 검색이 태국어 `หมูหมากช้าง` 으로 사이트 기록에 남아 있고, 크롬 번역이 그 태국어를 다시 `돼지막창` 으로 보여 줘서 한국어를 누른 것처럼 보였습니다. 태국어라 스크립트의 안전망에도 안 걸렸습니다. 1.11.1 부터 주소의 태국어가 **예전에 스크립트가 낸 번역인데 지금 용어집은 다르게 옮기는 말**이면, 용어집 값으로 바꿔 다시 검색합니다. 사이트의 최근 검색어에서 옛 항목을 지워 두면 더 깔끔합니다. 함께, 용어집 사본이 10분보다 오래됐으면 검색 전에 새로 받는 것을 잠깐(최대 1.5초) 기다리게 해서 다른 PC에서 고친 단어가 바로 들어가게 했습니다.
- **용어집 저장 토큰이 코드까지 고칠 수 있었음** — 1.11.0 에서 설정 패널에서 바로 GitHub 에 저장하게 하면서 브라우저에 토큰을 두게 됐는데, 용어집이 스크립트와 같은 저장소에 있으면 그 토큰으로 스크립트 코드도 고칠 수 있습니다(GitHub 토큰 권한은 파일 단위로 못 나눔). 새어 나가면 모든 PC에 나쁜 코드가 자동 업데이트됩니다. 그래서 용어집을 별도 저장소 `th-korean-glossary` 로 옮기고 토큰은 거기에만 쓰게 했습니다. 공개 저장소 변조 감시(`th-korean-private`)도 함께 만들었습니다. [보안](#보안-저장소-구성) 참고.
- **캐시가 옛 오역을 되살림** — 용어집에 `빗자루=ไม้กวาด` `도시락=กล่องข้าว` 를 넣은 뒤에도, 용어집이 작던 시절 AI가 낸 답(`ด้ามไม้กวาด` `อาหารกลางวัน`)이 검색어 캐시에 남아 있었습니다. 검색어가 통째로 용어집에 있으면 괜찮지만, `실내 빗자루` 처럼 모르는 말이 섞이면 캐시를 먼저 봐서 옛 오역이 그대로 나왔습니다. 1.9.1 에서 (1) 검색어 캐시를 한 번 비우고, (2) 용어집에 걸린 말이 하나라도 있으면 검색어 통째 캐시를 보지 않게 했고, (3) AI 모드에서도 용어집에 걸린 말은 프롬프트에 `빗자루=ไม้กวาด` 로 못 박아 넘깁니다.
- **옛 스크립트 감지** — 옛 `라자다 …` 스크립트가 같이 돌면 그쪽이 검색을 먼저 가로채 무엇을 고쳐도 옛 번역이 나옵니다(위 `도시락` 사례). 1.9.1 부터 버전 표시가 없는 `한` 버튼이 보이면 "옛 버전 스크립트가 함께 돌고 있습니다" 토스트를 띄웁니다.
- **폼 제출 핸들러의 하드코딩** — submit 가로채기가 라자다 전용 `#q, input[name="q"]` 로 검색창을 찾고 있어, 쇼피(`name="keyword"`)에서는 이 경로가 통째로 죽어 있었습니다. 사이트별 선택자를 쓰도록 고쳤습니다. 사이트를 추가할 때 이런 하드코딩이 남아 있는지 보세요.

## 쇼피 검색창 (실제 DOM 확인, 2026-09-20)

첫 화면(`shopee.co.th`)의 DOM을 직접 열어 확인하고 선택자를 맞췄습니다.

```html
<form role="search" action="/search" class="shopee-searchbar">
  <div class="shopee-searchbar__main">
    <div class="shopee-searchbar-input">
      <input type="search" name="keyword" class="shopee-searchbar-input__input"
             role="combobox" aria-controls="shopee-searchbar-listbox">
  <button type="button" class="btn ... shopee-searchbar__search-button">
```

확인한 것:

- 검색창은 `name="keyword"` `type="search"` 입니다. 이전 선택자 중 `form[action*="search"] input[type="text"]` 는 `type` 이 `search` 라 애초에 맞을 수 없었습니다. 클래스명보다 오래 가는 `name`/`type` 을 앞에 두고, 클래스 선택자는 뒤로 내렸습니다.
- 검색 버튼은 `type="button"` 이라 클릭해도 `submit` 이 나지 않습니다. 클릭을 직접 가로채야 합니다.
- 자동완성 목록 `#shopee-searchbar-listbox` 는 폼 안에 그려집니다(위젯 선택자에 걸림).
- 검색 버튼을 눌러 보니 SPA 전환이 아니라 `https://shopee.co.th/search?keyword=…` 로 통째 이동합니다. 쓰고 있던 주소 형식이 맞습니다.
- 입력창은 리액트가 물고 있습니다(`_valueTracker` 존재). 라자다에 쓰던 네이티브 setter + 추적기 무효화가 그대로 먹히고, 값이 되돌아가지 않습니다.
- 실제 페이지에서 판정 로직만 따로 태워 봤습니다. 검색창 Enter — 가로챔, 검색 버튼 클릭 — 가로챔, 검색창 밖 Enter — 통과.

선택자를 확인했으므로 **`broadInputFallback` 을 껐습니다.** 켜 두면 한국어가 든 아무 텍스트 칸(배송지, 리뷰 등)에서 Enter만 눌러도 검색으로 튑니다.

**검색 결과 페이지** — DOM을 직접 열어보지는 못했습니다. `/search` 로 바로 들어가면 쇼피 봇 감지가 `/verify/traffic/error` 나 캡차로 돌려보내 자동화 브라우저로는 열리지 않습니다. 다만 실제 사용 화면(2026-09-20)에서 결과 페이지의 검색창에 한국어를 넣고 검색하는 것이 동작했으므로, 그 페이지에서도 선택자가 맞는 것이 확인됐습니다. 헤더가 전 페이지 공용 컴포넌트라는 추정과도 맞습니다.

어긋나는 페이지가 나오면 **Tampermonkey 아이콘 → `검색창 인식 상태 확인`** 을 눌러 보세요. 검색창·위젯·버튼 중 무엇이 맞았는지, 문서 언어가 무엇인지 알려줍니다.

라자다는 실제 DOM을 확인하고 만들었으며 3차 테스트까지 통과했습니다.
